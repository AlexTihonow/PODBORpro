# Шаблон условий приёмки

## Образец: С-2 Регистрация и вход
**Готово, когда:**
- [ ] Регистрация с новой почтой → `201 Created`, в ответе токен.
- [ ] Повторная регистрация с той же почтой → `409 Conflict`, код ошибки `email_taken`.
- [ ] Та же почта в другом регистре (например, `IVAN@mail.ru`) → `409 Conflict`.
- [ ] Пароль короче 8 символов → `400 Bad Request`, код ошибки `validation_error`.
- [ ] Вход с верными данными → `200 OK`, в ответе токен.
- [ ] Вход с неверным паролем → `401 Unauthorized`, сообщение «Неверная почта или пароль».
- [ ] Вход с несуществующей почтой → `401 Unauthorized`, **то же самое** сообщение («Неверная почта или пароль»).
- [ ] Запрос к `/me` с просроченным токеном → `401 Unauthorized`.
- [ ] Запрос к `/me` с токеном, подписанным другим ключом → `401 Unauthorized`.
- [ ] В базе данных пароль хранится не открытым текстом (хэш).

**Как проверяется:** проверки REST-интерфейса в `server/internal/httpapi/auth_test.go`.

## Условия приёмки для задач недели 3 (до 09.10)

### С-4 Очередь и планировщик (Старший)
- [ ] Два обработчика не берут одну и ту же задачу из очереди.
- [ ] Упавшая задача автоматически повторяется с экспоненциальной паузой.

### СМ-3 Адреса вакансий (Младший)
- [ ] Постраничная выдача корректно отдаёт последнюю страницу.
- [ ] Пустая страница отдаёт пустой массив, а не ошибку.
- [ ] При `per_page > 100` запрос возвращается с ошибкой `400` или корректно ограничивается.

### СМ-2 Профиль (Младший)
- [ ] `PATCH`-запрос изменяет **только** переданные поля, остальные остаются без изменений.

### К-3 Вход и регистрация (Клиентская часть)
- [ ] Двойное нажатие на кнопку «Войти» не создаёт дублирующих запросов.
- [ ] Введённые данные не теряются при ошибке сети (форма не сбрасывается).

### К-4 Лента на заглушках (Клиентская часть)
- [ ] Вакансия без указания зарплаты отображается как «Зарплата не указана», а не ломает вёрстку.

### А-5 Приведение данных (Архитектор)
- [ ] Нераспознанная валюта/зарплата записывается как `null` (пусто), а не угадывается системой.

### А-9 Демонстрационный набор (Архитектор)
- [ ] 50 000 вакансий создаются одной консольной командой без ручного вмешательства.

### М-2 Сервис моделей (Машинное обучение)
- [ ] Эндпоинт `/health` отвечает «не готов» (например, `503`), пока модель загружается в память.

### Т-3 Сборщик HeadHunter (Инженер по тестированию)
- [ ] Сборщик корректно обрабатывает лимит в 2000 вакансий на запрос (дробит по дате/региону).
- [ ] Присутствует обязательный заголовок `HH-User-Agent`.
- [ ] При превышении лимита частоты запросов (rate limit) сборщик делает паузу и повторяет запрос.
