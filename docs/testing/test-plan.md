# План тестирования PODBORpro

## 1. Уровни проверок
1. **Модульные тесты**: пишут разработчики для своего кода (Go `testing`, `pytest`).
2. **Проверки REST-интерфейса**: инженер по тестированию по описанию API.
3. **Сквозные тесты (E2E) в браузере**: инженер по тестированию (Playwright).
4. **Нагрузочные тесты**: инженер по тестированию (неделя 8, k6).
5. **Проверка отказов**: инженер по тестированию (неделя 10).

## 2. Что проверяется в первую очередь
- **Приватность**: один пользователь не видит данных другого.
- **Цена ошибки**: поведение строго соответствует таблице 6.2 общего документа (утечки данных и падение системы недопустимы).

## 3. Инструменты (Чем)
- Go `testing`, `pytest` (модульные)
- Playwright (сквозные тесты)
- k6 (нагрузочные тесты)

## 4. Расписание (Когда)
- **Модульные и REST-проверки**: на каждый запрос на слияние (PR).
- **Короткие сквозные тесты**: на каждый запрос на слияние (PR).
- **Полные сквозные тесты**: перед каждым показом/демонстрацией.

## 5. Расположение тестов (Где лежат)
- `server/**/_test.go`
- `ml/tests/`
- `e2e/`

## 6. Процесс сообщения об ошибках
Ошибка оформляется как задача на доске со следующими полями:
1. Что делал (шаги воспроизведения).
2. Что ожидал.
3. Что получил (фактический результат).
4. Как повторить.
5. Серьёзность (см. ниже).

## 7. Серьёзность ошибок
- **Критическая**: утечка данных, падение системы. Чинится немедленно.
- **Высокая**: не работает главный сценарий.
- **Средняя**: работает, но только с обходным путём.
- **Низкая**: внешний вид, опечатки в текстах.
