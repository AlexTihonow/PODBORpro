# Анализ API HeadHunter для сборщика (Т-3)

## 1. Основные ограничения и параметры
- **Эндпоинт списка**: `GET https://api.hh.ru/vacancies`
- **Параметры**: `text`, `area`, `per_page` (макс. **100**), `page`, `date_from`.
- **Предел глубины выдачи**: API HH отдаёт максимум **2000 вакансий** на один поисковый запрос, независимо от количества страниц. 
  - *Решение*: сборщик должен дробить запросы по `date_from` (например, по дням) или по `area` (регионам), чтобы не упустить данные.
- **Детали вакансии**: список отдаёт краткую выжимку. Полный текст описания и поле `key_skills` доступны **только** при запросе `GET https://api.hh.ru/vacancies/{id}`.
  - *Решение*: на каждую вакансию из списка нужен отдельный запрос. Это основное узкое место по скорости.

## 2. Аутентификация и заголовки
- Обязательный заголовок: `HH-User-Agent`.
- Формат: `HH-User-Agent: PodborPro/1.0 (alex@example.com)`
- Без этого заголовка запросы будут отклонены с ошибкой `403 Forbidden` или `400 Bad Request`.

## 3. Rate Limiting (Ограничения частоты)
- При превышении лимита возвращается код `429 Too Many Requests` или `503 Service Unavailable`.
- В ответе присутствует заголовок `Retry-After`, указывающий время ожидания в секундах.
- *Решение*: сборщик должен читать `Retry-After` и делать паузу перед повтором.
